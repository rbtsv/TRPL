# Проекты
В рамках практической части курса вам будет предложено реализовать проект связанный с построением алгоритма разбора для некоторой задачи.

В качестве результата ожидается PDF-файл содержащий формальную постановку задачи (например в виде описания грамматики) и описание всех используемых алгоритмов для преобразования разобранной строки. Так же необходимо предоставить исходный код с достаточными комментариями для воспроизведение его работы.

Проекты специально даются в виде неформального описания. Создание формальной постановкой задачи является частью проекта. Предлагаемые темы:

- На вход подается регулярное выражение. Необходимо построить по нему ДКА посредством основе алгоритма Глушкова и написать LaTeX-код для диаграммы данного ДКА.
- По описанию PEG строить алгоритм для проверки строки на вхождение в его язык в виде монадических парсеров на Haskell.
- Построить систему верификации доказательств в минимальной логике (интуиционисткой логике включающей только импликацию) посредством просто-типизированного лямбда-исчисления.
- Реализовать интерпретатор (вместе с REPL) для любой адекватной версии LISP (cм. например LISP 1.5 Programmer's Manual).
- Написать тип представляющий TCP пакет и парсер из битовой строки в соответствующий тип данных в соответствии с RFC793. 
- Написать декодер формата DEFLATE описанного в RFC1951.
- Файлы в формате .env задают переменные окружения и активно используются в проектах на Python и JS/TS . Формат на первый взгляд кажется простым `VAR = value` и многие просто делают команду `source file.env` для обновления своих переменных окружения. Но это опасно, потому что там может находиться код на .sh языках! В то же время формат поддерживает извлечение значений из других переменных окружения подстановкой:

```
NAME = "Ivan"
LASTNAME = "Ivanov"
FULL_NAME = "$NAME $LASTNAME" # Значение будет вычислено "Ivan Ivanov"
```

Но запрещено исполнение кода (что-то в стиле `$(eval ...)`).
Сделать программу, которая безопасно обрабатывает .env файл и вычисляет все значения переменных с помощью PEG или других средств синтаксического анализа из курса
- Обобщить формат .json с поддержкой меток и ссылок на них. Например:
```
{
 universities: [ mipt@{"name": "MIPT", "address": "...", ... }, msu@{"name": MIPT", "address": "...", ... } ]
 "students": [
 	{name: "Ivan Ivanov", university:@mipt},  	{name: "Peter Petrov", university:@msu}
 ]

}
```
при обработке (трансляции в .json) в переменные будет подставляться значение, записанное в @-переменных
- Написать алгоритм, которая парсит описание правил .peg (например как в peggy.js без доп. хуков и вычислений) и возвращает .json со структурой [{"NT": "Нетерминал в левой части", "expr": {описание выражения с типом и из чего состоит}}]
- Написать алгоритм, переводящий конфигурационные файлы в формате TOML в формат JSON (и/или наоборот).

Если у вас есть своя идея для проекта, мотивированная, например, вашими рабочими задачами, то её выбор в качестве проекта можно обсудить с преподавателем.

Предполагается, что алгоритм разбора будет реализован на языке Haskell при помощи методов рассмотренных на семинарах. Разрешается использовать библиотеки парсерных комбинаторов (такие как Parsec).

Дедлайн сдачи проекта: до начала зачетной недели. При ранней отправке преподаватель может дать обратную связь по проекту. На зачетной неделе может быть организована устная беседа по коду проекта.
